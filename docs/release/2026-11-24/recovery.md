Require a fresh verified recoverable checkpoint, the recorded operational lead and the approved incident authorization/custody arrangement; record any single-operator limitation. **Frontend:** select the last verified compatible Lovable publication and obtain its actual asset/version evidence; redeploy/restore through the existing project after approval. Preserve internal authorization and exact JWT verification configuration. Validate unauthenticated denial, Owner/Manager/Staff boundaries, horizontal denial and appointment state without external notifications/calendar writes. The isolated runtime rehearsal compiled the actual integration API and worker factories and dependencies into ESM bundles, deliberately damaged each module and verified import failure, restored saved bundle bytes/hashes, imported the recovered code and invoked real handler factories. **Database:** an uncommitted migration failure can roll back transactionally, as rehearsed. Already committed additive onboarding changes should use a reviewed forward fix; rolling back the frontend does not authorize removing lifecycle guards or audit tables. Destructive changes and committed data loss require controlled restoration/precise repair to a separate compatible environment, verification and approved cutover. Never automatically reverse production migration history, replay seeds, drop lifecycle helpers or revive revoked keys. Migration filenames and managed timestamps may differ; compare bodies/hashes rather than reapplying by filename.

**Configuration:** restore approved prior values from the restricted recovery store after checking source/Edge/DB compatibility; never print values in tickets/logs. Keep integration scheduling paused while recovering; reinstate only the recorded scoped mapping after fresh synchronization and approval. Do not restore transient HTTP queues, expired booking tokens, invitation leases or historical requests as live work. Existing external calendar writes are outside this rehearsal.

**Post-recovery:** verify schema/catalog/ACL/constraints, tenant RLS, unbound identity denial, current profile status, revoked/suspended membership denial and fresh login/MFA through hosted Auth when authorized. Validate appointment conflicts, Kuwait times and idempotency locally first; use approved synthetic production fixtures only after authorization. ## Demonstrated CI defect and focused fix

Reproduction: provide a valid synthetic current-integration recovery envelope to the database CI entrypoint while mocking all database/AWS boundaries. Before this change, setup never consumed or materialized this input, so the existing `integration_recovery_config` admission failed with `private_path_required`; no successful backup/upload was possible. A custodian-only old ciphertext also cannot be authenticated by a new ephemeral verifier. Root cause: missing database runtime input plumbing, not a broken encryption or scope guard. Operational severity is P1 when scheduling is enabled against this schema; recurring backup readiness remains blocked while scheduling is disabled.

The smallest fix validates/encrypts the approved v1 envelope to the existing combined recipients, passes its private ciphertext only during the existing database export call, and wires one database-only environment-secret reference. Regression evidence demonstrates the same original failing flow now succeeds with synthetic boundaries, while absence/malformation/partial encryption/overwrite attempts fail closed. Genuine local age encryption proves both separately generated custodian and ephemeral identities decrypt identical envelope bytes; no plaintext settings file, private-key artifact, external request, DB dump, storage upload or production data was involved in these tests. The code is prepared locally and is not installed in production/CI until protected publication.
