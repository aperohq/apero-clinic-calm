## Exact remaining authentication acceptance

Fresh read-only hosted policy inventory belongs to the parent release inventory. It must be interpreted independently from local acceptance. An enabled TOTP provider and a displayed enrolled factor do not establish usable MFA challenge or recovery. The current Account implementation calls `listFactors` and `getAuthenticatorAssuranceLevel`; it has no enrollment/challenge/recovery flow. Before closing T-064, an authorized operator must use a designated synthetic Owner to enroll, verify correct and incorrect/expired challenges, establish AAL2 session behavior, rehearse the approved lost-factor/recovery path, verify retained-session effects and remove only the recorded test factor/account changes. Record sanitized outcomes, never seeds, QR contents, tokens, passwords or recovery material. If launch policy requires dashboard self-service MFA, a separately scoped implementation is required; policy cannot be silently weakened.

Production horizontal and role checks require approved designated synthetic identities and sessions. Fresh metadata/RPC grant checks and historical deployment evidence can support configuration consistency, but cannot be substituted for actual Manager/Staff hosted Auth behavior.

3. Inventory all child references and compare with expected fixture counts. 4. Prepare a reviewed transaction/dry run with exact IDs and expected row counts. Obtain explicit founder approval before any production account/data deletion or external cleanup.
