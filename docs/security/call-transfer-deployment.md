# Guarded call transfer — 2026-10-05

1. **Already existed:** clinic `fallback_phone`, structured `opening_hours`, timezone, Owner-only Settings RPC/UI, signed Retell routing, call ownership/RLS, the published Human Escalation path/helper, Requests, and specific booking/calendar/unknown-answer fallbacks. Retell already supports native warm transfers with dynamic destinations and a failure edge. No clinic transfer activation setting, live transfer node or transfer-event handling existed. The agent inherited its account-level webhook route.
2. **Implemented:** a default-off clinic activation flag, backend eligibility gate, atomic one-attempt reservation in existing `voice_call_state`, one native warm-transfer node, safe outcome metadata, signed transfer webhooks, and adapters to the unchanged Human Escalation save helper. No new provider, Requests subsystem, voicemail, queue, IVR, retry loop, medical triage or messaging integration.
3. **Exact triggers:** an explicit request to speak to clinic staff/a human, or an existing human-escalation case where direct staff conversation is needed now or the caller accepts a live connection. Follow-up-only escalation and normal supported requests do not authorize transfer. Backend requires an allowlisted human category, the qualifying flag, an activated clinic, a valid configured international destination, valid current clinic hours/timezone, a provider phone call, and an unclaimed attempt. A destination matching the inbound clinic number is rejected to avoid a self-transfer loop. Specific booking/calendar/unknown-answer fallback behavior remains unchanged and is not automatically transferred. The live node has no caller destination argument; it uses only the freshly returned trusted backend variable. Authorization is cleared before each gate, and the deterministic edge requires permission plus a nonempty destination.
4. **Before/success:** in the established caller language: “I’ll try to connect you with the clinic team now.” No success claim before connection. Native warm transfer waits for human detection, uses the agent/provider caller ID rather than caller-ID override, rings for 20 seconds, and has a 15-second detection timeout. There is no success continuation that saves a failure request. Only a signed `transfer_bridged` event for a reserved, owned call records `success`; caller arguments cannot assert success. Success is terminal against late failure/started events. Transfer events add no transcript or provider payload storage and do not overwrite existing conversations. Normal completed/analyzed call processing remains intact.
5. **No destination/busy/no-answer/failure:** missing/invalid destination, disabled activation, unsupported call type, self-transfer or dependency failure prevents dialing and routes to existing Human Escalation. Native rejection/busy/no-answer/timeout/technical failure uses its failure edge and signed cancellation event, with no second attempt. Cancellation can save follow-up even if the caller leg cannot resume. Both event and in-flow failure retention call the existing `humanEscalationFollowUp` helper with the same concise canonical reason/category, so event retries and function retries share one request. Supplied/known contact data is minimal: supplied name and confirmed phone, or the existing trusted telephony patient-side number when present in the signed event. Requests stays `kind=message`, Open, clinic/call scoped, with automatic timestamp and “Human assistance required.” After confirmed retention: “The clinic team could not be reached right now. Your request has been passed to them for follow-up.” If saving fails or its result is missing: “The clinic team could not be reached right now, and I couldn’t pass your request to them. Please contact the clinic directly.” No callback-time promise. Specific cause labels are used when a trusted cause is supplied; unavailable/unknown cause is `provider_error`, never a guessed SIP status.
6. **After hours:** outside the structured hours, or with missing/invalid hours/timezone, do not dial. Say: “The clinic team is not currently available for transfer. I can pass your request to them for follow-up.” Existing Human Escalation runs if assistance is still wanted; declining follow-up saves nothing. Weekly periods, breaks, closing boundaries and clinic timezone are enforced. No hours are inferred from knowledge-base prose or caller input.
